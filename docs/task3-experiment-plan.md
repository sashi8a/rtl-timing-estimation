### Why residual prediction was dropped

A sufficiently expressive direct predictor can in principle learn the relationship
between BOG timing and target timing, including a correction. Residual prediction
can still change inductive bias and optimization, so equivalence of practical
results is not guaranteed. With limited time, defer this additional calibration
pipeline and comparison to focus on two more distinct research questions. This
is a scope decision, not experimental evidence that residual learning fails.

### Shared preparation before concurrent experiments

- Use the finalized, provenance-validated release; do not train against artifacts
  being regenerated by the Task 2 flow.
- Fix and record entire-family train/validation/test membership before fitting or
  tuning. Exact membership remains to be chosen.
- Fit preprocessing only on training data. Keep all paths and all four views of
  a register bit in the same partition. Never copy an endpoint label onto paths
  and treat those paths as independent labeled examples.
- Establish a naive predictor: the median arrival of training register bits,
  predicted for every validation/test bit. The median matches the proposed MAE
  objective. An uncalibrated SOG arrival reference is an optional additional
  timing-informed sanity check, not a replacement for the naive baseline.
- Share dataset identity, partition manifest, metric implementation, units, and
  result schema between tracks. Keep held-out test evaluation until experiment
  configurations are fixed.

### Track A: balanced training weights

Compare a compact direct endpoint tree model with uniform per-register weights
against the identical model with family/design-balanced weights. A proposed rule
assigns equal total weight to each training family, equal shares to its designs,
then equal shares to each design's eligible bits. Normalize weights to mean one
to avoid unintended changes in regularization scale. Select the tree estimator
and a small tuning budget before execution; this endpoint model is not claimed
to reproduce RTL-Timer's custom path-level XGBoost objective.

Hypothesis: balancing improves performance across families rather than allowing
large designs to dominate. Risk: small designs receive high per-register weight.
Only weights change within this comparison.

### Track B: smooth-max training

Compare a small shared path-level MLP using hard-max endpoint aggregation against
the same MLP using a smooth approximation that sharpens toward max. Supervise
each register bit using its endpoint arrival label. Fix the path inputs, feature
preprocessing, representation/fusion choice, architecture, paired seeds, and
training budget across the two conditions. Use uniform endpoint weights in both
conditions initially so weighting does not confound the pooling experiment.

Before implementation, specify the pooling equation, temperature units/schedule,
variable-path-count handling, padding masks, and inference rule. Ordinary
log-sum-exp has a path-count-dependent offset; a normalized alternative also has
a bias relative to the maximum. Neither should be chosen without documenting
its implications. Hypothesis: sharing gradient among competitive paths early in
training improves optimization. No path-level ground truth is claimed.

### Parallel execution and reporting

Once shared preparation is frozen, the CPU tree experiments and GPU MLP
experiments can run independently without waiting for each other's results.
This does not require multiple agents. Keep track-specific outputs separate;
avoid concurrent dependency-lock edits or changes to shared data/splits.

Four main configurations remain: uniform tree, balanced tree, hard-max MLP,
and smooth-max MLP, plus the naive baseline. Repeated neural seeds are repeats,
not additional hypotheses. Defer combining weighting with smooth-max until the
individual effects have been evaluated and only if time remains.

Proposed metrics: primary macro design MAE in ns, pooled MAE, family-level MAE,
RMSE, and correlation where defined. Inspect high-arrival endpoint errors using
a predeclared rule. Report per-design results and neural seed variability;
register bits within a design are not independent evidence of generalization.
Use matched within-track comparisons for causal interpretation. A tree-versus-
MLP difference alone cannot identify the effect of weighting or pooling.

### Inputs: explicit allowlists, no target-netlist features

Each example is one eligible register bit. IDs locate records and determine
partitions; family/design/endpoint names, aliases, pin names, proof metadata,
target cell statistics, and target timing reports are never predictor inputs.
BOG-derived timing and statistics are allowed because they are available before
target timing is generated. Existing path samples stay fixed across all runs.

For **T0/T1**, concatenate these groups for each of SOG, AIG, AIMG, and XAG:

- Endpoint: `driving_register_count`, `primary_input_count`, `bog_arrival_ns`,
  `bog_rank_percentile`. The last is an input computed from BOG timing; it does
  not introduce a ranking prediction objective.
- Design: `register_bits`, `combinational_operators`, `max_combinational_depth`,
  `net_count`, and the six AND/OR/NOT/XOR/MUX/BUF operator counts.
- Paths: retain count; summarize each of 17 path quantities using mean, maximum,
  and population standard deviation over that endpoint's retained paths. The
  quantities are arrival, depth, the six operator counts, and sum/mean/standard
  deviation of each of fanout, capacitance, and slew. A singleton has zero
  standard deviation. This produces 66 columns per view before train-constant
  removal; some intentional redundancy remains with endpoint arrival.

These 264 candidate features combine the paper's design/cone/path levels in a
simple endpoint vector. Omit `path_operator_count` (duplicates depth in this
release), variance (redundant with standard deviation), categorical rank group,
and audit-only fields. Export exact ordered column names. Drop only columns
constant in training; no feature selection using validation/test labels. Trees
need no feature scaling. Missing required values or views cause a preparation
failure, not silent row removal or imputation.

For **N0/N1/N2**, use all four representations. Each view's bag contains all
retained paths for an endpoint; the current release has **1–33 paths per bag in
each representation**, with 1,304 bags per view. Each path receives the same
17 quantities listed above, a register-versus-primary-input launch indicator,
and that view's two endpoint cone counts plus its ten design quantities. Add a
four-category one-hot representation indicator. Recommend **one shared path MLP
across all four views**, conditioned on that indicator, rather than four separate
networks: we have only 716 proposed training endpoint labels. Thus the shared MLP
has 34 candidate inputs before train-constant removal. Shared versus separate
parameters remains a recommendation for user review. Do not repeat
endpoint maximum BOG arrival or rank on each path: that would provide a shortcut
around the path aggregation under investigation. Omit the critical/random path
flag initially. These are deliberate feature deviations, identical for N0/N1/N2.

Standardize neural numerical features separately within each representation,
using training data only, with each path weighted
by `1 / bag_size` when estimating means and variances, so every endpoint has
equal influence on the scaler. Keep all paths; do not truncate, resample, or
duplicate them to equalize bag lengths. Standardize shared context the same way;
leave one-hot indicators unscaled.
Use one common column mask across views: remove a numerical column only if it is
constant within every training view. For a column constant in one view but not
the others, keep the column and use scale 1 in that view. Validation/test values
use the stored training mean and scale, including for constant training columns.
Keep all four representation indicators. No view-dependent input dimensions.

### Tree experiment: defaults and balancing interpretation

Recommend `HistGradientBoostingRegressor` with absolute-error loss, 200 trees,
learning rate 0.05, at most 15 leaves, minimum 10 samples per leaf, L2 penalty 1,
random seed 0, and `early_stopping=False`. All features are numerical. These are
small-model starting settings, not claimed optimal settings. The estimator
supports the required loss and sample weights; disabling internal early stopping
avoids an internal register-level validation partition. See the
[official estimator API](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html).

No hyperparameter sweep in the initial experiment. Run both settings with the
same configuration and inputs. If a correctness or serious optimization problem
requires changing the protocol, document the reason and amend it before test
evaluation, rerunning both members. Do not tune one arm more than the other.

For training family f with D_f designs and design d with n_d bits, use:

```
T0: w_r = 1
T1: w_r = N_train / (F_train * D_f * n_d)
```

This makes the mean weight one and each family's total weight equal. Under the
proposed partition, T1 weights range from approximately 0.146 to 13.259. The
9-bit PWM256 family receives as much total weight as the 349-bit JPEG family.
The weight concentration corresponds to a Kish effective count of about 182
(versus 716 rows); this is a weight diagnostic, not an estimate of independent
observations. Do not cap weights in this first comparison: that would change
the proposed treatment. Record this risk even if the result is negative.

**Metric alignment caveat:** equal-family/equal-design weighting corresponds
to a macro-family average of design MAEs, whereas the primary metric weights
every design equally. Those objectives differ when families contain different
numbers of designs. Keep macro-design MAE primary as proposed, and always report
macro-family-of-design-MAE as a secondary metric. Improvement on one does not
imply improvement on the other.

### Neural experiment: aggregation, bias, and controls

Use a shared MLP with hidden widths 64 and 32, ReLU hidden activations, and one
softplus output score per path. The scores are latent quantities supervised
through the endpoint loss, not independently validated physical path delays.
All three conditions use uniform endpoint MAE loss, one loss per bit, batch size 32
bits with all their paths, AdamW (learning rate 0.001, weight decay 0.0001),
gradient norm clipping at 1, and no dropout or batch normalization.

Scale labels by s, the **training-set median arrival in ns**, without centering.
Require s > 0 and verify nonnegative training labels before using this output
parameterization. Work in y/s units, then multiply predictions by s for all
reported metrics. This is scaling, not residual prediction or SOG calibration.

For real path scores z_1,...,z_n, define:

```
N0: m = max(z_1, ..., z_n)
N1/N2 during smoothing: A_tau = tau * (logsumexp(z / tau) - log(n))

m - tau * log(n) <= A_tau <= m
```

Normalization removes ordinary log-sum-exp's upward offset for equal scores,
but **does not remove bias relative to the maximum**. For unequal scores the
pooled value is lower; the bound depends on the number of paths. For example,
scores [1, 0] with tau=0.1 yield about 0.931 rather than 1. This is a mathematical
example, not an experimental result. Single-path bags equal their score at
every temperature. Repeating an entire bag preserves the normalized result;
duplicating only one path generally changes it.

Use numerically stable log-sum-exp, exclude padded slots with a mask, and count
only real paths in n. Never pad with unmasked zero scores. Use a fixed path order
and the same hard-max implementation in all arms, including its tie rule.
Normalized pooling gives softmax-distributed gradients; hard max normally gives
gradient only to a winning path. Smoothing may help optimization, but can also
push the largest score upward to compensate for its downward aggregation bias.

Pool paths separately within each representation, then combine the resulting
four endpoint scores. N0/N1 use their arithmetic mean. N2 uses
`alpha = softmax(a)` with four global trainable logits initialized to zero, so
every alpha starts at 0.25, and prediction `sum_v alpha_v * score_v`. The logits
are shared across all endpoints and jointly trained with the MLP at the same
learning rate, with no weight decay on logits; there are no per-design gates or
auxiliary view losses. All models have one loss on the final endpoint prediction.
Only N2 has these four additional parameters. Log the weights, but do not call
them feature importance: even a shared representation-conditioned network can
rescale its view predictions and compensate for the weights.

Proposed schedule for 200 epochs:

- N0: hard max for all 200 epochs.
- N1/N2: epochs 1–150 use tau_e = 0.1 * (0.005 / 0.1)^((e-1)/149), in scaled
  target units; epochs 151–200 use exact hard max.
- All retain the same optimizer and fixed learning rate throughout. All use
  hard-max validation and hard-max inference. Complete the same epoch budget;
  select the lowest macro-design validation MAE among epochs 170, 180, 190, 200
  in each run, breaking ties in favor of the earlier epoch. The common candidate
  set ensures N1/N2 have at least 20 hard-max fine-tuning epochs before selection.

In physical units, tau_ns = s * tau. For the largest current bags (n=33), the
worst-case gap bound starts at about 0.350*s ns and ends at 0.0175*s ns before
hard-max fine-tuning. That initial bias is material. Log actual max-minus-smooth
gaps and errors against bag size on train/validation; fine-tuning is a mitigation,
not a guarantee. Do not call N1/N2 merely smoother versions of the same forward
prediction at finite temperature: it is a changed training objective.

Use paired seeds 11, 22, 33, with identical initial MLP parameters and minibatch
orders within each N0/N1/N2 seed group. Initialize N2 logits without changing the
MLP initialization or minibatch RNG stream. Plan nine neural runs. Run the first
seed group to measure runtime; any reduction to one seed must be based on
resource constraints, not which condition wins. Record every run, including failed runs, and never select
a best seed for reporting. Seed variability measures optimization variability,
not uncertainty across unseen circuit families.

### Baselines and evaluation contract

- Naive: ordinary median of training register arrivals, reused unchanged for
  every validation/test bit. This minimizes unweighted training MAE, not the
  macro-design objective. Do not fit separate family or test-design medians.
- SOG reference: existing SOG endpoint arrival, with no fitted correction.
- T0 is the main learned baseline; N0 is the matched neural control.
- Primary: mean of per-design MAEs, in ns. Each design receives equal weight.
- Secondary: pooled MAE/RMSE, per-design MAE/RMSE/signed bias, per-family pooled
  MAE, and macro-family-of-design-MAE. Keep the last two distinctly named.
- Pearson and Spearman correlations are descriptive; report pooled and
  per-design values only when both vectors have nonzero variance and at least
  two observations. Otherwise report undefined, not zero. Pooled correlation
  can reflect between-design differences; it does not add a ranking objective.
- Tail diagnostic: within each evaluated design, label arrivals at or above its
  90th percentile as high-arrival bits, include ties, and report threshold,
  count, and MAE. This uses labels only for evaluation, not input construction or
  training selection. Do not use percentage error as the primary metric.

Freeze configurations and neural checkpoints using train/validation only, then
evaluate all conditions and references in one test stage. No train+validation
refit in this initial study. Report T1-minus-T0, each paired N1-minus-N0, and
each paired N2-minus-N1 MAE
difference, together with absolute scores and per-design results. A negative
difference favors the intervention. Report all three seeds and mean/spread;
do not treat register rows as independent samples in significance claims.
With this split, validation/test each contain one design per family, so their
macro-design and macro-family-of-design metrics coincide; the distinction still
matters for the training objective and training diagnostics.

### Relation to RTL-Timer and implementation order after review

RTL-Timer section 3.2, equation (3), predicts path scores and supervises the
maximum at each bit-level endpoint. N0 follows that aggregation idea. Section
3.3 uses design, cone, and path features; section 4.1 reports a substantially
larger MLP (hidden dimension 512). Our smaller shared, view-conditioned MLP, MAE training choice,
direct four-view endpoint tree, feature summaries, and smooth-max schedule are
documented project choices, not a full reproduction. We do not infer a specific
loss from equation (3)'s generic `LossFunc`. No signal-ranking head, signal-level
ensemble, WNS/TNS prediction, or synthesis optimization is included. Paper
accuracy numbers are not directly comparable to our dataset and label flow.
