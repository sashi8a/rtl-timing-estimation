# Task 1 runbook

## Environment

The tested server is Ubuntu 24.04 x86-64 with 8 logical CPUs and 31 GiB RAM.
Docker is available through `sudo -n docker`. The EDA image is pinned by digest in
`configs/eda.json`. No GPU is needed for this stage.

Install uv 0.11.19 using Astral's release for the host architecture. From the repository:

```bash
uv sync --locked
```

This creates `.venv` using Python 3.12.6 from `.python-version`. Do not install
packages into system Python. Use `uv sync --locked --no-dev` for pipeline-only servers.

Fetch the exact image from `configs/eda.json` (initial download requires network):

```bash
sudo docker pull openroad/orfs@sha256:7f9c688e71cd49379b9e9a45a4558724e3eda501eaaaf11bc9b77382a3fe647b
```

Execution containers have no network and run as the invoking user's UID/GID.
The tool binaries are enabled by sourcing the image's ORFS `env.sh`.

## Pilot

```bash
uv run rtl-timing fetch gcd
uv run rtl-timing generate gcd --representation sog
uv run rtl-timing verify-equivalence gcd --representation sog
uv run python scripts/validate_artifacts.py data/processed/gcd/sog
```

Repeat `generate`, `verify-equivalence`, and validation for `aig`, `aimg`, and `xag`.
The formal command records `passed` or `unproven` in `equivalence.json`; inspect that
file rather than treating command completion as proof.

## Collection

```bash
uv run python scripts/run_collection.py --workers 2
```

The manifest records 19 retained designs and their dependencies; DCT is recorded separately in `deferred_designs.json` after a bounded-runtime exclusion. Each design is fetched
from a pinned revision. Failed stages are recorded in `data/collection_runs/<run-id>.json`;
a candidate is not automatically a validated dataset member. To rerun selected designs:

```bash
uv run python scripts/run_collection.py --workers 2 --designs timer32 uart
```

Do not run two jobs for the same design/representation concurrently. Each EDA stage
has a ten-minute timeout; timed-out containers are explicitly stopped. Inspect raw logs before modifying constraints or excluding
failed designs. No target labels are generated by these commands.

## Artifacts and provenance

`data/raw/<design>/provenance.json` records fetched file URLs and SHA-256 hashes.
`data/processed/<design>/<representation>/` contains synthesis/STA scripts, logs,
JSON graphs, mapped Verilog, topology candidates, endpoint/path Parquet tables,
coverage summary, and formal verification status. Generated artifacts are ignored
by Git. Fetch commands preserve source notices; do not infer a circuit's license
from ORFS's build-script license.

The original GCD pilot is archived; GCD now uses the same explicit common
constraints in the manifest: 10 ns clock, 0.1 ns input/output delays, 0.01 ns input
transition, 1 fF output load, no extracted parasitics, no reset case analysis.
These are controlled experimental conditions, not claimed design specifications.
The Task 2 pilot checks matching SDC hashes before joining labels.

For an interrupted run with unchanged inputs/configuration, add `--resume-existing`. Completed artifacts are reused. Do not use this option after changing RTL, constraints, libraries, or feature settings. Four workers were used after checking server memory usage.

Generate the shareable inventory using `uv run python scripts/summarize_collection.py`. It reports actual completion and proof status; it does not equate an unproven result with a functional failure.

After collection, run these checks and capture the final artifact identities:

```bash
uv run python scripts/reextract_collection.py
uv run python scripts/validate_collection.py
uv run python scripts/summarize_collection.py
uv run python scripts/snapshot_provenance.py
```

The hash snapshot identifies final inputs and outputs; it is not a historical execution trace. Raw reports permit extraction to be rerun without repeating synthesis.
